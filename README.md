# Rajesh Sharma — Portfolio

A personal portfolio site built with [Next.js 15](https://nextjs.org/) (App Router + Turbopack), React 19, MUI 7, Tailwind CSS 4 and TypeScript. It is deployed as a static export to GitHub Pages.

---

## Quick Start (local)

### Prerequisites
- **Node.js 20+** (tested on Node 20 and 24)
- **pnpm** — install with `npm install -g pnpm` if you don't have it

### Steps

1. **Clone the repo and enter it:**
   ```bash
   git clone https://github.com/rsharma33/rsharma33.github.io.git
   cd rsharma33.github.io
   ```

2. **Install dependencies:**
   ```bash
   pnpm install
   ```

3. **Start the dev server:**
   ```bash
   pnpm dev
   ```

4. **Open the app:** http://localhost:3000

The dev server uses Turbopack with hot module replacement — edits under `src/` appear in the browser immediately.

> **Note on native build scripts:** pnpm 10+ blocks post-install scripts by default, which makes `pnpm install` fail with `ERR_PNPM_IGNORED_BUILDS` for `sharp`, `@tailwindcss/oxide`, `@parcel/watcher` and `unrs-resolver`. This repo ships a `pnpm-workspace.yaml` that approves exactly those four packages, so a plain `pnpm install` works out of the box. If your pnpm version reads a different key, run `pnpm approve-builds` once and accept those four.

### Using npm instead of pnpm
A `package-lock.json` is also committed, so npm works too:
```bash
npm install
npm run dev
```

## Available Scripts

| Command | What it does |
| --- | --- |
| `pnpm dev` | Start the dev server on port 3000 (Turbopack, HMR) |
| `pnpm build` | Production build / static export into `out/` |
| `pnpm start` | Serve the production build |
| `pnpm lint` | Run ESLint (`eslint-config-next`) |
| `pnpm debug` | Start the dev server with the Node inspector attached |
| `pnpm deploy` | Build and publish `out/` to the `gh-pages` branch |

```bash
pnpm dev -- -p 4000
```

## Docker

Running in a container gives a consistent environment across machines.

### Prerequisites
- Docker with Docker Compose v2 (`docker compose`, not `docker-compose`)
- The compose file attaches to an **external** network named `web_bridge`. Create it once:
  ```bash
  docker network create web_bridge
  ```

### Commands

The compose file is `docker-compose.yml`, so no `-f` flag is needed:

1. **Build and start in the foreground:**
   ```bash
   docker compose up
   ```

2. **Start in the background:**
   ```bash
   docker compose up -d
   ```

3. **Follow the logs:**
   ```bash
   docker compose logs -f
   ```

4. **Stop and remove the container:**
   ```bash
   docker compose down
   ```

5. **Rebuild after Dockerfile or dependency changes:**
   ```bash
   docker compose up --build -d
   ```

### Makefile shortcuts
Equivalent, shorter forms — run `make help` for the full list:
```bash
make build     # build the image
make up        # start in the foreground
make start     # start detached
make logs      # follow logs
make shell     # open a shell inside the container
make down      # stop and remove
make clean     # remove containers, images and volumes
```

### Reaching the app in Docker
The `web` service uses `expose: 3000` rather than `ports:`, so port 3000 is reachable from other containers on the `web_bridge` network (e.g. a reverse proxy) but **not** from your host. To hit it directly at http://localhost:3000, add a port mapping to the `web` service in `docker-compose.yml`:

```yaml
    ports:
      - "3000:3000"
```

### Live reload in Docker
The container bind-mounts the project directory (with `node_modules` and `.next` kept inside the container), so local edits are picked up and Next.js HMR works without rebuilding the image.

## Deployment

The site is a static export published to GitHub Pages:

```bash
pnpm run deploy
```

This runs `predeploy` (`pnpm build` plus `touch out/.nojekyll`) and then pushes `out/` to the `gh-pages` branch via `gh-pages`.
